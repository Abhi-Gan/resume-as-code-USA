# Writing Style Guidelines

Personal phrasing preferences for this candidate's resume bullets. Optional input — if this file doesn't exist for a given user of this repo, skip it and infer style from reference resumes only.

Copy this file to `writing-style.md` and edit or delete each section to match your own preferences. None of the sections below are required — the Resume Generation Agent applies whatever rules are present and ignores the rest.

## General

- Any sentence-level habits you want kept consistent, e.g. dropping leading articles ("a"/"the") to save space, or a preferred sentence rhythm.
- Whether to vary action verbs between bullets to avoid repetition (e.g. "built", "shipped", "designed").

## ATS

Notes on how aggressively to optimize for Applicant Tracking Systems, e.g.:

- Always mirror keywords/acronyms from the JD when accurate.
- Emphasize transferable skills for career-change applications.

## Reusing wording across resumes

- Whether bullets describing the same underlying fact should reuse the exact phrasing from a prior tailored resume, rather than being reworded from scratch each time.

## Bolding density

- How many bolded phrases per bullet you want (e.g. exactly one: the headline metric or most distinctive deliverable), and any ceiling on how dense bolding should get.

## Keyword / tag style

- What counts as a valid `keywords` entry for you (e.g. concrete technologies/tools/algorithms only, not invented capability-summary phrases).

## Template-specific notes

- Any per-template overrides, e.g. preferred section titles when using `tech-compact`'s split Experience/Research sections.
